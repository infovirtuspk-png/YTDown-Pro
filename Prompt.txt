# YTDown Pro — Complete Deep-Detailed Desktop Application Development Prompt

## 1. PROJECT TITLE

**Application Name:** YTDown Pro

**Application Type:** Professional Windows Desktop Media Downloader & Converter

**Primary Platform:** Windows 10 / Windows 11 — 64-bit

**Application Architecture:**

- Electron.js
- Node.js
- HTML5
- CSS3
- JavaScript ES6+
- Bootstrap 5
- SQLite
- Bundled yt-dlp
- Bundled FFmpeg

**Core Principle:**

Build YTDown Pro as a completely standalone desktop application. The application must contain its own yt-dlp and FFmpeg binaries and must NOT require the user to separately install yt-dlp, FFmpeg, Python, Node.js, PHP, MySQL, or any third-party downloader API.

The application may require normal internet connectivity to retrieve publicly accessible media information/content from supported platforms, but all application-side processing must be handled locally.

Only support downloads that the user owns, has permission to download, or is otherwise legally entitled to access. Do not implement DRM bypassing, private-content extraction, authentication bypassing, CAPTCHA bypassing, geo-restriction bypassing, or other access-control circumvention.

---

# 2. PROJECT OBJECTIVE

Create a professional desktop application inspired by the workflow and simplicity of modern online video downloader applications, but redesigned specifically for Windows desktop.

The application should provide a beautiful, modern, responsive and animated interface where users can:

1. Paste a supported public media URL.
2. Analyze the URL.
3. Retrieve media information.
4. Display thumbnail, title, duration and metadata.
5. Display available download options.
6. Select video/audio format.
7. Select quality.
8. Select download location.
9. Start the download.
10. Monitor real-time progress.
11. Pause/cancel where technically supported.
12. Retry failed downloads.
13. Convert supported media to audio formats using FFmpeg.
14. View completed downloads.
15. Open downloaded files.
16. Open download folders.
17. Manage download history.
18. Configure application settings.
19. Manage bundled engine status.
20. Update/check the downloader engine safely.
21. Use Dark, Light and System themes.
22. Use responsive UI text and adaptive layouts.
23. Use smooth animations throughout the application.

# 66. DATABASE ABSTRACTION

Do not put raw SQL queries throughout UI code.

Use repository/service architecture:

```text
UI
 ↓
Service
 ↓
Repository
 ↓
SQLite
```

Example:

```text
DownloadRepository
HistoryRepository
SettingsRepository
LogRepository
EngineRepository
```

# 68. IPC API DESIGN

Expose only controlled APIs through preload.

Example:

```text
window.ytdown.analyzeUrl()
window.ytdown.startDownload()
window.ytdown.cancelDownload()
window.ytdown.pauseDownload()
window.ytdown.getDownloads()
window.ytdown.getHistory()
window.ytdown.openFile()
window.ytdown.openFolder()
window.ytdown.selectFolder()
window.ytdown.getSettings()
window.ytdown.updateSettings()
window.ytdown.getEngineStatus()
```

Do not expose:

```text
child_process
fs
shell
process
```

directly to renderer code.

# 73. SEARCH ENGINE / SUPPORTED PLATFORM ARCHITECTURE

The application should not hard-code UI assumptions that only one source is supported.

Create a provider abstraction:

```text
MediaProvider
    ↓
Provider Adapter
    ↓
Media Engine
```

The UI should be able to display:

```text
Supported Source
Unsupported Source
```

The backend/provider layer decides actual support.

Do not claim support for a platform unless the bundled engine and current application implementation actually support it.
